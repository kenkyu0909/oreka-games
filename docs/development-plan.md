## 以下は0.4時点の記録（旧仕様）

### RE:FRAME 0.4 開発・検証計画

依頼: 同時選択を廃止し1体ずつ行動するターン制へ。攻撃演出を明確にする。途中のユーザー確認なしで各段階を検証する。

## 採用するルール

- 各ラウンド開始時の素早さで先手を決定（同速はシード抽選）。先手が選択・行動し、その結果を見て後手が選択・行動する。同時入力は不要。
- 各陣営は1ラウンド1行動。任意交代も自分の手番の1行動。交代の割り込みは廃止。
- 未行動のカードが倒れた場合、そのラウンドの行動は失う。戦闘不能による補充は無料。補充後に次ラウンドの順序を決める。
- 状態異常はラウンド末に処理。60ラウンド判定を維持。写真生成・ダメージ式は変えず、進行ルールは battle-v2 とする。

## ステップと完了条件

1. [x] エンジン: 片側の入力だけで1行動を解決。手番外・二重入力拒否、交代、KO、状態異常、再現性、CPU完走を自動検証。
2. [x] CPU/通信: CPUは自身の手番だけ判断。サーバーで手番を検証。2クライアント、再接続、タイムアウトを検証。
3. [x] 演出: 技カットイン → 属性別の攻撃 → 着弾 → ダメージとHP変化。順序が視覚的に明確で、演出中は次の攻撃を重ねない。スキップ/低減設定も維持。
4. [x] UI: 現在の手番・次の手番を表示。手番外の選択を無効化。画面移動、詳細、降参で進行が固まらない。
5. [x] 総合検証: Node/実WS/ブラウザテスト、スマホ画面の実画像確認、ビルド、ドキュメント更新。不具合があれば該当ステップに戻り修正。

## 制限

この作業内で開発・検証を繰り返す。無期限のバックグラウンド開発や実機未検証部分の完全性は保証しない。実機Safari/Android、通信の不安定な実回線、長期運用は別途確認が必要。

## 検証で見つけた問題と修正

- おまかせ停止がCPU側の予約も消していた → CPUの手番は自分の自動操作とは独立して再予約。ブラウザ回帰テストを追加。
- 演出中に次の通信状態が来ると前の演出を途中破棄する構造だった → Promiseキューで1行動ずつ再生。実2クライアントで攻撃側の順序 [P2, P1] を記録して検証。
- 退室後に残った旧ルームのキューで対戦が復活する可能性 → 接続世代を検査し、退室・新ルームで無効化。
- 手番ラベルがカードの見出しに重なる → フィールド上部に専用レーンを確保。
- 小画面のスキップがほかの操作に重なる → 演出中の操作列を再配置。
- カットイン/飛翔/着弾をブラウザのDOM変化で記録し、HPが着弾時に初めて減ることを自動検査。390pxの実レンダリング画像も確認。
