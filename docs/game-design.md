# RE:FRAME（仮称）— 写真カード対戦ゲーム仕様書

更新日: 2026-10-11
状態: 基本仕様を合意。カード作成、3体編成、CPU対戦、友達との合言葉ルーム対戦を実装済み。戦闘数値は初期バランスとして調整中。

## 1. 合意済みの方向性

### 体験・対象

- 写真からキャラが生まれる楽しさ、強い写真を探す楽しさ、頭脳戦、楽しい対戦を両立する。
- 当面は身内向け。将来的な一般公開には興味がある。
- スマホ対応のWebゲーム。開発にはAIを活用し、無料運用を目指す。
- Raspberry Piもホスティング候補。採用サービスは未定。
- 外部の画像解析AIを必須にしない。

### UI・見た目（0.6）

- Master Duel / Duel Linksのような「対戦中心のゲーム画面構成」を参考に、既存作品の素材・ロゴは使わずオリジナルで制作。
- 黒・赤を基調にしたシリアスなTCG風。写真を枠付きカードとして扱い、ホームからCPU・友達対戦へ入る。カードはオレカバトルのようなアーケード収集カードの雰囲気を参考に、独自の明るい紙面と黒/金の装飾枠・大きな写真で表現する。
- スマホ縦持ちの通常対戦はスクロールなし。対戦カードを大きくし、能力値公開・相手の技一覧は表示しない。履歴・自分の技説明は別ダイアログ、能力詳細は作成画面のみ。
- 最新の技・ダメージ等だけを中央のメッセージ帯に表示。攻撃・被弾・交代等を順に演出する。
- 効果音と豊富な演出。音は初期オフ。演出オフ、端末の低減設定、高速・スキップにも対応。
- 画面の小さすぎる横持ち等ではスクロールを許可し、操作を切り捨てない。
- タイトルは提案段階の「RE:FRAME（リフレイム）」。名称の最終決定・商標調査は未実施。

### キャラクター作成

- 写真の被写体は自由。写真入りカードにする。
- 色、画素数、輪郭等、複数の画像特徴を能力に変換する。
- 同じ画像ファイル・同じ生成ルール版なら、同じ能力・属性・レベル・技になる。
- 写真の加工や再圧縮で能力が変わることは許容する。加工を攻略として認める。
- 写真と能力の関係は、可能ならわかりやすくする。
- キャラ間の大きな能力差を許容・希望する。均等な能力合計にはしない。
- 育成は不要。ログイン・キャラの永続保存も不要。
- 再生成のため、プレイヤー自身が元の画像ファイルを保持する。

### 10種類の能力

1. HP
2. 物理攻撃
3. 物理防御
4. 特殊攻撃
5. 特殊防御
6. 素早さ
7. 急所
8. 状態異常耐性
9. 回復力 — 自分が使用する回復技の効果量。自動回復ではない。
10. 貫通力 — 相手の防御・特殊防御の一部を無視する力。上限を設ける。

キャラ能力としての命中・回避は設けない。急所等の能力値は、そのまま確率（%）を表す値ではない。戦闘中の具体的な変換式は `docs/battle-rules.md` を参照。

### 属性・レベル・技

- 属性は地・水・炎・風・光・闇の6種類。初期版では1体につき1属性。
- 独自の属性相性を設ける。実装した初期相性表は `docs/battle-rules.md` を参照。
- レベルは1〜12。写真から固定で決める。
- レベルは通常ダメージに直接掛けず、特定技の効果条件に使う。
- 低レベル・高レベル・同レベル、それぞれに使い道を作る。
- 技は制作者があらかじめ登録し、キャラ生成時のルールで1体4つを割り当てる。
- 技ごとに使用回数（PP）を設ける。
- 技ごとに命中率を設け、基本100%。低命中・高威力の技も許容する。

### キラ加工

- 能力と見た目のレアリティは分離する。レアリティは能力や技に影響しない。
- キャラ生成のたびに加工をランダム抽選する。同じ写真でも見た目は変わる。
- 作り直して好きな加工を狙うことを許容する。
- 記念用のカード画像を書き出せるようにする。画像出力はゲーム用キャラデータの保存ではない。

### バトル・閲覧範囲

- 技はプレイヤーが選択する。ルーレットは初期仕様に採用しない。
- 初期の対戦は3体チームで、場には1体ずつ出す。交代あり。
- 両者が技を選び決定したら、素早さ順に1回ずつ行動する（0.5でユーザーが明示）。選択は同時、攻撃の演出は順次。0.6で先制技を追加し、技の優先度が同じ場合に素早さ順となる。
- 1試合は約5分。一定の運要素を許容する。
- 友達とのオンライン対戦が初期版の必須要件。CPU対戦もあるとよい。
- 離れた場所の各自のスマホから、ログインなしの合言葉（ルームコード）で入室する。
- 写真は本人と対戦相手に表示してよいが、一般公開はしない。
- ダブルバトルは将来の候補。
- バトルはポケモン、レベル・加工表現は遊戯王を参考とする。既存作品の画像・ロゴ等は流用しない。

## 2. 今回実装したカード作成試作

カード作成はViteとブラウザ標準UI、JavaScript。友達対戦用にNode HTTP + WebSocketサーバーを追加。DB・アカウントはない。

- JPEG・PNGからのカード作成。12MB以下、2,400万画素以下、各辺20,000px以下。
- 10能力、6属性のうち1つ、レベル1〜12、4技・PP・命中率を表示。
- ランダムな加工、カード名の編集、PNG画像のダウンロード。
- 能力、技、画像特徴の表示切替。
- 外部画像を使わないオリジナルのサンプルイラスト3種。
- スマホ幅、キーボード操作、解析中・エラーの表示に対応。
- 入力写真は端末内のWeb Workerで解析。アップロードや永続保存は行わない。
- タブを閉じる・再読み込みするとキャラを破棄する。

**3体編成・CPU戦・合言葉ルーム対戦まで実装済み。** 詳細は `docs/battle-rules.md`。CPU戦は端末内、友達対戦はサーバー上で戦闘を進行する。

## 3. 試作の生成ルール `photo-v3`（能力計算はv1/v2と共通）

以下の式・技の数値・抽選確率は開発用の仮調整値であり、ユーザーが個別に承認したバランスではない。ルールを変える際はバージョンも更新する。

### デコード・再現性

- 固定バージョンの `jpeg-js` と `fast-png` で画素を読み取る。
- 能力解析にはブラウザのCanvasデコード・画像縮小を使わない。
- 元画像の格納画素から64×64の中心点サンプリングを行い、透過は白に合成する。
- v1/v2/v3ではICC色管理、PNG gamma、EXIF回転情報は無視する。アニメーションは対象外。
- 表示用画像も同じデコーダーから作成。EXIF回転に依存する縦向き写真は、端末の写真アプリと向きが異なる場合がある。
- 対応外形式（HEIC/WebP/GIF等）は明示して拒否する。任意の被写体という要件と、対応ファイル形式は区別する。
- 端末間のブラウザ差を避ける実装にしているが、iOS Safari・Android実機の確認は未実施。完全な実機検証済みとはしない。
- SHA-256は写真IDに使用。能力はハッシュではなく画像特徴から算出する。短縮IDは表示用で認証には使わない。

### 特徴と能力

各特徴は0〜1000に正規化し、組み合わせて能力範囲に変換する。具体式は `src/game.js` を正とする。

| 能力         | 元にする特徴           | 試作範囲 |
| ------------ | ---------------------- | -------- |
| HP           | 明るさ・元画像の画素数 | 60〜400  |
| 物理攻撃     | 彩度・明暗差           | 15〜250  |
| 物理防御     | 左右対称度・暗さ       | 15〜250  |
| 特殊攻撃     | 色の多様性・彩度       | 15〜250  |
| 特殊防御     | 左右対称度・明るさ     | 15〜250  |
| 素早さ       | 輪郭の細かさ・縦長度   | 15〜250  |
| 急所         | 明暗差・輪郭の細かさ   | 1〜100   |
| 状態異常耐性 | 左右対称度・彩度の低さ | 1〜100   |
| 回復力       | 緑の割合・明るさ       | 1〜100   |
| 貫通力       | 輪郭の細かさ・明暗差   | 1〜100   |

属性は暗さ・明るさ・色の優勢度から分類。レベルは対称度・色の多様性・縦長度から決める。猫・車等の意味的認識はしない。

### 4技の割当て（photo-v2）

旧版の4役割固定を廃止。48種類の正規ライブラリ（各属性6種＋無属性12種）から、写真の11特徴を順序固定の32bit整数ハッシュにし、固定疑似乱数・能力による重みで選択する。同じ属性でも別の4技を持てる。

1. 自分と同属性の命中100%の攻撃技から1つ（基本技限定ではなく、連撃/先制/吸収等も候補）。
2. 全攻撃技から1つ。他属性を含む。
3. 回復/補助または条件付き攻撃から1つ。
4. 全技から1つ。

既出技と効果が完全に同一の純粋な強化技は除外し、常に4技が重複せず攻撃技が最低2つある。属性一致・攻撃適性・回復力・素早さ・急所・貫通・レベルが選ばれやすさに影響する。加工抽選・端末の乱数・ファイルIDには依存しない。

2/3連撃、先制、吸収、反動、攻撃/防御/速度の強化・弱体、状態異常と浄化、貫通、急所、瀕死時/相手の状態異常/レベル条件を用意。詳細は[全48技](move-library.md)、処理は[battle-v4](battle-rules.md)。物理/特殊「適性」の技は本人の高い攻撃能力に対応する種別へ確定する。

### レア技の割当て（photo-v3）

v2の4技を一度そのまま生成し、独立した固定saltと11特徴の32bit整数ハッシュを用いて約5%の付与判定を行う。当選時だけ4枠目を20種類のレア技から選んで置換する。候補の選択重みは自属性3、無属性1.2、他属性0.8。1カード最大1技。全てのレア技に非ゼロの選択機会があり、最低2つの攻撃技を維持する。

新規生成はphoto-v3。既存photo-v2の技ライブラリと割当て関数を変更せず、明示的なv2の再生成では同じ4技を維持。統計的な約5%であって、20枚ごとの保証や毎回のランダム抽選ではない。箔加工とは独立する。PP2〜3/率5%は初期調整値。

### photo-v1の互換

明示的にv1を指定したカードは従来の「属性基本技 / 属性波動 / レベル条件技 / 回復か防御」を再現する。新規生成はv3で、10能力・属性・レベルは変わらない。全3版を通信時に正規値へ再計算する。旧戦闘ログ自体の再生互換は保証しない。

### 加工の抽選

ノーマル55%、シルバーフォイル25%、ホログラム15%、プリズム5%。ブラウザの乱数を使い、写真特徴・能力・技とは分離する。画面の加工はCSS、出力画像はCanvasで静的に表現するため、表現は完全に同一ではない。

## 4. 実装した対戦範囲

- 属性相性、ダメージ、急所、状態異常、回復、防御強化、貫通率上限。
- 双方が行動を確定後に公開・解決。任意交代は技より先、同速は抽選。
- 戦闘不能後の交代、PP切れの反動技、60ターン上限、引き分け、降参。
- 対戦画面では相手の数値能力・技一覧を公開しない。選択中の技・交代先と乱数シードは通信上も非公開。能力の通信上の秘匿は未実装。
- CPU3段階、おまかせ、高速、再戦、固定シード、ログのダウンロード。
- 2人用の6文字ルームコード。復帰用の秘密トークンは別途発行。
- サムネイルの縮小・メタデータ除去、サイズ制限、メモリ内一時保持と破棄期限。
- 切断90秒の復帰猶予、選択120秒、再読み込み復帰、部屋の期限切れ。

具体値は実装時に置いた初期バランスで、今後実際の写真とプレイで調整する。初期の身内向け利用を対象とし、大規模公開向けの運用・不正対策は別途必要。

## 5. プライバシー・運用上の留意点

- 対戦時に相手へ見せた写真のスクリーンショット等まで防ぐことはできない。
- ルームの一時状態とキャラの永続保存は別物。保存不要でも通信の進行管理は必要。
- サーバーで能力を再生成しても、クライアントの画像特徴が正しい証明はできないため、改ざんを完全には防げない。
- 無料サービスには利用枠や仕様変更がある。無制限・恒久無料は保証しない。
- Raspberry Piでは電気代・回線・HTTPS・外部公開の安全性を検討する。
- このプレビューは開発用であり、本番公開・写真の一般公開を意味しない。

## 6. 開発の順序

1. 写真からカードを作成（実装済み）。
2. 対戦エンジン・3体編成・CPU対戦（実装・自動テスト済み）。
3. 合言葉ルームによる友達対戦（実装・2ブラウザで検証済み）。
4. 実際の写真・対戦を通して、能力差と約5分の試合時間を調整。
5. 必要に応じてダブル、ルーレット、一般公開を検討。
