# RE:FRAME（リフレイム）— 写真カード対戦

写真から作った3体で戦う、スマホ対応Webゲーム。**カード作成・CPU対戦・友達との合言葉ルーム対戦**を実装しています。

## 0.8 — 伝説のカード図鑑 / RARE AWAKENING

**[強力カード10枚のフォルダ・保存手順](public/strong-cards/README.md)** · **[原本PNG10枚をZIPで保存（約40MB）](public/strong-cards/strong-cards-10.zip?raw=true)**

- ホームの竜カードをタップ、またはカード作成の「★ 伝説のカード図鑑」から10枚を選択。全6属性・全10枚が異なるレア技持ち。能力・4技を確認し、「この画像でカードを作る」→「チームに追加」。面倒な保存・再アップロードは不要です。
- 図鑑は軽量JPEGだけを先読み。選んだ1枚の原本PNGを取得し、サイズ・SHA-256を照合して、普通の写真と同じWorkerで再解析します。取得中の閉じる操作でキャンセルでき、失敗時は既存カードを保持します。
- レア技を持つカードの誕生時に **RARE AWAKENING**。全滅決着の最後のKOに **FINAL BREAK**（相討ちはDOUBLE BREAK）。勝敗画面には自分のデッキ3枚も表示。操作を遮らず、演出OFF/動きを減らす設定/演出スキップに対応。音は初期OFFの独立設定です。
- 10枚のAI生成イラスト原本、軽量プレビュー、能力表、原本ハッシュ、ZIPを `public/strong-cards/` に収録。各PNGは4,000×6,000px、約3.5〜3.8MiB。「最強」の厳密な保証ではなく、84,000パターンから高能力と技構成を狙って選んだ候補集です。加工の詳細・弱点・原本の保存方法はフォルダ内READMEを参照してください。
- **photo-v3 / battle-v4 / protocol 5 は変更なし。** 能力式・レア出現率・既存写真の能力/技・ダメージ・PP・行動順・乱数に変更はありません。キラ加工のみ従来どおり抽選です。

**0.7.1: スマホから試す入口を追加。** ホームの「スマホで遊ぶ」から、今開いているHTTPSプレビューのQRコード・URLコピー・対応端末の共有を利用できます。QRは端末内で生成し、写真・編成・ルーム情報は含めません。タッチ操作・入力欄の文字サイズ・ノッチ用余白も調整しました。**サーバー稼働中のお試し用で、常設公開ではありません。** [スマホでの開き方](docs/mobile-play.md)。

**0.7: 強力なレア技を20種類追加（通常48＋レア20）。** [レア技一覧](docs/rare-moves.md)。新規生成のphoto-v3では、写真特徴からの固定抽選で約5%のカードの4枠目に1技だけ入ります。PPは2〜3回。最大威力180、先制連撃、強力吸収、攻撃＋強化、先制浄化回復など。金色の技ボタン/レア表示、専用カットイン、ゲーム内ルールの全20技一覧も追加。加工のレアリティとは独立し、同じ写真の再読み込みで抽選結果は変わりません。

**0.6.1: 技選択ボタンに基礎威力を常時表示。** 連撃は「威力22×3」、回復/補助は「威力—」。相性や能力を計算した予測ダメージではありません。カードは明るい紙面を残し、太い黒/金の枠・大きな盾型属性マーク・下部の名前帯へ刷新。小さな装飾英字を削除し、写真を拡大しました。作成画面・編成・保存PNGも同じ方向に更新しています。能力・技の生成規則は変更していません。

**0.6: 新しい写真カードの技を48種類へ拡張しました（photo-v2 / battle-v4）。** 連撃・先制・吸収・反動・強化/弱体・浄化など、効果の違う4技を写真の特徴から決定します。同じ属性でも組み合わせは固定ではありません。両者が決定してから、交代 → 先制技 → 通常技の順に行動し、同じ優先度では素早さ順。攻撃演出は1体ずつです。

## 1人ですぐ試す

1. ホームの「デュエルを始める」で、サンプル3体のCPU戦を開始。
2. 4つの技から選ぶ。「交代」タブから控えのカードに交代。
3. 「おまかせ」「高速」で最後まで自動テストもできます。
4. 難易度・乱数シードを変えたい場合は、ホームの「CPUと腕試し」から設定。

自分の写真を使う場合は、「カード作成」で写真を選び「チームに追加」を3回。編成画面で先発を変更できます。

### 黒×赤のゲーム画面（UI 0.6）

- ホーム / カード作成 / 編成 / バトルを切り替えるアプリ型UI。タイトルは仮称 **RE:FRAME**。
- 写真を大きく見せる明るい紙面と黒・金の装飾枠、黒と深紅のフィールド。対戦カードは左右に大きく配置。一般的な縦持ちスマホでは、カード・最新行動・4技を1画面に配置。
- 最新の行動だけを強調し、過去ログは「履歴」で開きます。対戦中は能力値・相手の技一覧・相性による予測ダメージを表示しません。HP・状態異常・自分の技/PPを残し、10能力は作成画面で確認できます。
- 大きな技名カットイン → カードの攻撃動作・属性別の飛翔 → 着弾 → ダメージ数字・HPバー変化を順に再生。回復、防御、交代、急所、戦闘不能、勝敗にも演出。右上の **✦** で演出、**♪** で効果音を切替。
- 効果音は初期オフ。ユーザー操作後にのみ合成音を再生。端末の音量にも注意してください。
- 端末の「視差効果を減らす」を尊重し、「高速」や「演出スキップ」でも待ち時間を省けます。設定は音・演出の2項目だけlocalStorageに保存。
- 画面高さ570px以下の横持ち・小画面では、操作を隠さないためスクロールに切り替えます。履歴・詳細・編成の追加設定内も必要に応じてスクロールします。
- 降参はバトル右上の「☰」から。誤操作防止の確認画面があります。

画面の演出用スナップショットと確定済みの戦闘状態は分離しています。連撃も着弾ごとにHPを減らし、回数を表示。技ボタンには「先制」「吸収」「3連撃」などのタグ、詳細には効果・命中率・1発あたりの威力を表示します。

### 通常48種＋レア20種と写真の再現性

- [全48技の一覧](docs/move-library.md)。各属性6技＋無属性12技。旧版の「基本・波動・レベル条件・回復か防御」の固定4枠を廃止。
- 写真の11特徴から固定ハッシュを作り、能力による重み付きで重複なしの4技を決定。最低2技は攻撃、先頭は自分と同属性の命中100%の攻撃。別属性の技も覚えます。
- 2/3連撃、先制、HP吸収、反動付き大技、攻撃/防御/素早さの強化・弱体、毒/やけど/鈍足/回復封印、浄化、貫通、急所、瀕死時/状態異常時/レベル条件の攻撃。
- 新規生成は `photo-v3`。10能力・属性・レベルの計算はv1/v2と同一です。最初の3技はv2と同じで、約5%の固定抽選に当たった場合のみ4技目をレア技に置換。明示的な `photo-v1` / `photo-v2` カードは旧技のまま再現し、サーバーも全3版を再計算します。写真を再生成すると最新v3になります。
- 加工の再抽選では技は変わりません。同じファイルと同じルール版なら同じ技です。異なる写真でも解析特徴が同一なら同じ結果になります。
- 進行は `battle-v4` / 通信はprotocol 5。古い戦闘リプレイの互換は保証しません。

### CPU・テスト機能

- 3段階のCPU（おためし / ふつう / 手ごわい）。難易度で能力を水増しせず、判断だけを変えます。
- 連撃を含む期待ダメージ、先制での撃破、吸収・反動、状態異常・浄化、強化/弱体、回復、交代を評価。プレイヤーの選択を盗み見しません。
- 乱数シード指定、同じ条件で再戦、戦闘ログのJSON出力。
- 手動とおまかせの切替、高速進行、降参、タブ内の戦績。
- 戦闘不能・交代・PP・急所・貫通・回復・防御強化・状態異常・60ターン判定。

### 写真カード

- JPEG/PNGから10能力・6属性のうち1つ・レベル1〜12・4技を生成。
- 同じファイル・同じ生成ルール版なら同じ能力。キラ加工だけ再抽選。
- カード名の変更、記念用PNGのダウンロード。
- 作成・CPU対戦では写真を外部へ送信しません。

### 友達との対戦

- 双方で3体を選び、「友達と対戦」から部屋作成 / 合言葉で入室。
- 同じ画面で招待リンクをコピー可能。部屋は2人用です。
- サーバーが双方の行動を非公開で保持。両者の決定がそろったら、素早さ順にHP・PP・勝敗を解決。
- 相手に届くのは決定済みかどうかだけで、選んだ技・交代先は解決まで非公開。確定後の変更・二重入力・古いシーケンスを拒否。
- 再接続・再読み込み復帰、時間切れ、降参、退室に対応。

## 起動

### Windows：ダブルクリックで起動（おすすめ）

1. [Node.js公式サイト](https://nodejs.org/ja)から **Node.js 24 LTS** をインストールします（npmも含む標準設定でOK）。すでに22.12以上が入っていればそのまま使えます。
2. この作業ブランチをcloneしたフォルダを開きます。以前cloneした場合は、先にそのフォルダで `git pull --ff-only` して更新してください。
3. フォルダ直下の **`start-game.bat`** をダブルクリックします。ZIPで取得した場合は、先にプロジェクト全体を展開してください。BATだけ別の場所へ移動しないでください。
4. 初回は必要なパッケージを取得 → ゲーム画面をビルド → 対戦サーバーを起動。準備ができたら既定のブラウザで **http://localhost:3000** が開きます。

**起動中の黒いウィンドウは閉じないでください。** 終了はウィンドウで **Ctrl+C**（確認が出たらY）、またはウィンドウを閉じます。管理者として実行する必要はありません。

- 初回・依存関係更新後・Node.js変更後にはインターネット接続が必要です。2回目以降は準備済みのパッケージを再利用します。画面は毎回ビルドするので、コード更新も反映されます。
- ブラウザが開かなければ、起動完了メッセージを確認して `http://localhost:3000` を手動で開いてください。
- `Node.js was not found`：Node.jsをインストールし、起動ウィンドウを閉じてからやり直してください。ターミナルから実行した場合はターミナルも開き直してください。
- ポート使用中：先に開いているゲームのウィンドウを終了してください。他アプリは自動終了しません。必要ならコマンドプロンプトで `set PORT=3001` → `start-game.bat` と実行すると `http://localhost:3001` を使えます。
- パッケージ準備失敗：ネット接続、ディスク空き容量、フォルダの書き込み権限を確認。エラー表示は消さずに残します。依存ファイルを手で壊した場合は、サーバーを終了して `node_modules` を削除し再起動すると再取得できます。
- Windowsファイアウォールの設定を自動変更したり、ソフトを管理者権限でインストールしたりはしません。サーバーは従来どおり `0.0.0.0` で待ち受けます。
- **このBATだけでインターネット公開されるわけではありません。** スマホの `localhost` はスマホ自身を指します。スマホで写真解析も使うには、別途HTTPSの公開・共有先が必要です。LANのHTTPアドレスだけでは写真解析できない場合があります。

### コマンドで起動（Windows / macOS / Linux）

Node.js **22.12以上**（24 LTS推奨）。

```sh
npm ci
npm run build
npm start
```

画面と対戦サーバーが同じ `0.0.0.0:3000` で起動します。ローカルPCでは `http://localhost:3000`。Arenaではポート3000のライブプレビューを開いてください。ポートを変更する場合は `PORT=8080 npm start`。

ホームの **「スマホで遊ぶ」** を開き、PC画面のQRをスマホのカメラで読み取ってSafari/Chromeへ移動できます。すでにスマホでArenaを使っている場合は、プレビューを新しいタブで開きます。PCの編成は引き継がれないため、スマホでサンプルまたは写真から開始します。Arena側のアクセス制限・サーバー停止中は開けません。

**スマホからアクセスする際はHTTPSが必要です。** LANのHTTPアドレスでは画像解析用Web Cryptoが使えない場合があります。localhostまたはHTTPSのセキュアコンテキストを使ってください。

### 開発

対戦サーバーとViteを別々のターミナルで起動します。

```sh
# ターミナル1
npm start

# ターミナル2
npm run dev
```

フロントは `0.0.0.0:5173`、`/socket` はViteが内部の対戦サーバーへプロキシします。ブラウザからlocalhostの別サービスを直接呼びません。Arenaの `.e2b.app` ホストを許可しています。

`npm run preview` はビルド済みフロントを4173で確認する用途。友達対戦を使う場合は、こちらも別途3000のサーバーが必要です。CPU対戦はフロントだけでも動きます。

### ラズパイ等への配置

- Node.js 22対応の64bit OSを推奨。上記の `npm ci → npm run build → npm start` を使用。
- 対戦には常駐Nodeプロセスが必要。DBは不要です。
- 本番公開ではCaddy/Nginx等でHTTPSとWebSocketのリバースプロキシを設定してください。
- プロキシは元のHostを保持してください。WebSocketのOrigin検査で使用します。
- 接続が同じプロセスに届く単一サーバー構成。複数インスタンスへの負荷分散は未対応。
- ラズパイ実機での検証は未実施です。ホスティング先の作成・公開デプロイも今回行っていません。

## プライバシー・制限

- アカウント不要。キャラの永続保存なし。リロードでローカル編成は消えます。
- カード作成・CPU対戦の写真は端末内のメモリのみ。
- **友達対戦で初めて**表示用に縮小した写真（280px以下）をサーバー経由で相手に共有します。元画像は送信しません。
- 写真・戦闘状態はルームのメモリに一時保持。待機10分、終了後5分で破棄。双方が明示的に退室した場合やサーバー再起動でも破棄。ディスク / DB保存はありません。
- ルーム復帰用トークンだけをsessionStorageに保持。写真・能力は保存しません。90秒以内の切断復帰、同じタブでの再読み込み復帰に対応。
- 対戦相手によるスクリーンショット等は防げません。
- 能力非表示は対戦画面の表示方針です。現在の通信状態やテスト用JSONログには相手の能力・技も含むため、通信解析から能力を隠す仕組みではありません。選択中の行動はサーバーだけに保持します。
- サーバーは受信した特徴から能力と技を再生成しますが、写真と特徴の対応を証明する仕組みはありません。**身内向けであり、一般公開のランキング向け不正対策ではありません。**
- JPEG/PNG、12MB以下、2,400万画素以下、各辺20,000px以下。HEIC/WebP/GIF等は未対応。
- `photo-v1` / `photo-v2` / `photo-v3` はICC/gamma/EXIF回転を反映せず格納画素を使用するため、写真アプリと向きが異なる場合があります。
- 記念用の出力カードを再入力しても元のキャラは復元できません。再生成には元の写真を残してください。
- ダブルバトル、育成、アカウント、公開マッチング、ランキングは未実装。
